# 品質ジャッジ（LLM-as-a-Judge）

## 目的

各Phaseの成果物（research.md / analysis.md / proposal.md）を**ルーブリックで定量採点**し、品質ゲートとして機能する。
出典・設計根拠は `references/verification.md` の P4。

## 絶対ルール（バイアス対策）

LLM-as-judge には提示順バイアスがある（[arXiv:2406.07791](https://arxiv.org/abs/2406.07791)）。これを前提に:
1. **順序入替で2回採点する**。1回目と2回目で対象（主張リスト・提案）の提示順を逆にし、スコアが大きくぶれたら「判定不安定」と報告。
2. **棄権を許容する**。判断材料が足りない項目は無理にスコアせず「判定不能」とする。曖昧を通過させない。
3. **自分(judge)も誤りうる**ことを前提に、確信度を併記する。

## ルーブリック（各0.0–1.0）

| 指標 | 観点 | 1.0の条件 | 0.0の条件 |
|------|------|----------|----------|
| factual accuracy | 主張がソースで支持されるか | 全主張ALIGNED | NOT_ALIGNEDが複数 |
| citation accuracy | URL実在＋主張対応 | 全URL実在・対応 | DEAD/捏造あり |
| completeness | 調査軸の網羅 | 全軸カバー | 主要軸に欠落 |
| source quality | 一次/二次・信頼度 | 一次中心 | 二次・単一ソース偏重 |

## 出力フォーマット

```markdown
## Judge レポート: {対象Phase}

### スコア（順序入替2回の平均と差分）
| 指標 | 1回目 | 2回目(順序逆) | 平均 | 安定性 | 確信度 |
|------|-------|--------------|------|--------|--------|
| factual accuracy | 0.x | 0.x | 0.x | 安定/不安定 | 高/中/低 |
| citation accuracy | ... |
| completeness | ... |
| source quality | ... |
| **総合** | | | **0.x** | | |

### 棄権した項目（判定不能）
- {項目}: {なぜ判定できないか}

### 検出した問題（要対応）
1. {NOT_ALIGNED/DEAD/欠落}: {詳細とPhase内の位置}

### 停止条件の判定
- 総合スコア: {0.x}
- **{≥0.7 → 通過 / <0.7 → 要改善。2回連続で<0.7なら「rio確認が必要」と明記}**
- ループバック回数: {n}/2（上限超なら人間判断へ）
```

## 注意
- 採点は「通すため」でなく「漏れを捕まえるため」。甘くしない。
- ただし完璧な成果物は存在しない。致命的問題と許容可能な不確実性を区別する。
- **最終検証者は人間（rio）**。judgeはゲートであって最終承認者ではない。
- **実装難度（build工数）・ownership/保守を減点軸にしない**: ルーブリックは factual/citation/completeness/source のみ。feasibility/effort は含まない。野心的な「作る」提案を工数・保守を理由に低評価しない（コストはAI速度に再基準化済み・工数の舵取りは Phase D で人間が行う）。
