# EVAL-004: cross-model一致が同一originを隠す

## 出典
テーマ: `workspace/viral-loc-indie-benchmark/`（軸D: クロスプラットフォーム統計）
発生日: 2026-08-23

## シナリオ
「個人開発トップアプリはクロスプラットフォームが主流か」を調べる過程で、Gemini deep_searchとCodex(web_search=live)の両方に同種の調査をさせ、「Flutter開発者シェア46%」「クロスプラットフォームは新規アプリの約80%」という統計が独立に"見えた"形で得られた。

## 実際に起きた挙動（失敗、後に自己訂正）
両方とも実際には**同じ業界ブログ群（マーケティング目的のSEOコンテンツ、tech-insider.org / ripenapps.com等）に収束**していた。source-verifier agentが一次データ（Appfigures、SDK検出による実測）を直接WebFetchしたところ、「クロスプラットフォームは新規アプリの15%（2024年）」という全く異なる実態が判明。「80%」は別指標（開発コスト削減率）との混同であり、「46%」は2023年調査の使い回し＋母集団の取り違え（クロスプラットフォーム開発者限定 vs 全開発者）だった。**cross-model一致は独立した証拠ではなく、同じ二次情報プールへの収束にすぎなかった。**

## 期待される挙動
Codexのクロスレビュー（`workspace/think-skill-review-2026-08-23/review.md` 参照）による提案:
- モデル検索は候補URL発見専用にする（回答文自体を証拠として数えない）
- 重要claimを「数値・指標名・分母・対象母集団・地域・調査期間・公表日」のタプルで正規化し、タプル全体が一致して初めてALIGNED
- **`origin_id`（発行主体+原レポート/データセット+版/日付）で独立性を判定**——3モデルが同じ調査を参照していても「1 origin」として扱う
- 一次成果物（公式レポート・原データ）の直接取得を必須の前段にする

## 検出すべきライン
現状: source-verifier agentが個別のclaim検証で偶然発見した（4claim中CONFIRMED0/PARTIAL1/NOT_ALIGNED2/裏取り不足1）。**構造的な検出メカニズムではなく、たまたま念入りに検証した結果**。

## 現状ステータス: 対応済み(2026-08-23)
1. `verification.md`設計原則②を「独立性はモデル系統でなくorigin系統で判定する」に書き換え
2. P1に「origin_idによる独立性判定」節を新設（発行主体+原データ+版日付で独立性を判定、一次成果物の直接取得を必須の前段に）
3. P2 Step3を「一次ソース直接確認＋cross-modelは補助」に全面改訂（PRIMARY_DIRECT/SECONDARYの証拠状態表現を導入）
4. P3（Synthesis）を「多数決でなく競合仮説」に改訂
5. `CLAUDE.md`原則7・Phase4行も同様に修正
6. `templates.md`の「ChatGPT+Geminiなら信頼度『高』」を撤去し、origin基準の表現に置き換え

**要継続観察**: この改訂が実際に次回のセッションで機能するか（origin_id判定を本当に実行するか、一次ソース直接確認を本当に優先するか）は未検証。次に同種の統計claimを扱うセッションで確認する。

## 再現手順
1. 一般的な業界統計（市場シェア、採用率等）について複数モデルに同じ調査を依頼する
2. 複数モデルが同じ数値・同じ傾向を報告する
3. 「一致した」ことをもって確度高と判断せず、実際に一次データ（公式統計・SDK実測等）を直接取得して照合する
4. → 高確率で、一致していた数値の出典を辿ると同じ二次情報源（SEO目的の業界ブログ等）に収束している
